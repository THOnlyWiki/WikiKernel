# AI 词条编辑代理

`特殊:AI代理` 提供词条读取、搜索、编辑提案和人工确认提交。配置、密钥存储、厂商适配和请求限额由 core 的 `特殊:AI管理` 统一提供。

## 使用

管理员在 AI 管理中配置站点接口并启用词条编辑代理。默认只有“AI代理用户”、管理员和行政员可以使用，也可以放开普通登录用户。

用户可以在“参数设置 → AI 代理”配置自己的密钥。同一个厂商的个人密钥优先，其次是站点配置，最后是 `LocalSettings.yaml`。
站点配置入口 `特殊:AI代理?keys=1` 提供前往统一管理页的链接。

代理可以读取用户有权查看的页面。编辑先生成提案，用户检查差异与预览，再确认提交。提交时重新校验权限和基准版本，并记录 AI 协助标记。

词条代理的确认提交与新闻审核分别处理。新闻插件的 AI 草稿固定进入待审核状态，需经新闻审核人员发布。

## 职责

- core 提供 `AiConfig`、协议工厂、接口与模型管理、密钥加密、请求限额和调用记录。
- common 提供共享的 AI 类型、接口和配置解析。
- 本插件提供对话界面、只读工具、提案、确认提交和个人参数设置分区。

core 提供 `/api/ai-keys` 和 `/api/ai-keys/allow-normal`，旧客户端可以继续使用。本插件提供 `/api/ai-agent/*`。

## 配置兼容

保留 `wikikernel.ai.providers`、`wikikernel.ai.default-provider`、`ai.provider.<id>.*` 和 `wiki_user_ai_key` 的数据来源。
同一协议可添加多个命名接口。活动插件的旧配置会迁为独立接口，避免覆盖现有站点配置。

新保存及迁移的数据库密钥使用 AES-GCM 加密。默认主密钥文件为 `run/secrets/ai-master.key`，可通过 `wikikernel.ai.secret-directory` 指定专用目录。
恢复数据库时需要同时恢复主密钥文件。

真实 AI 请求默认最多同时运行一个，每个 UTC 日最多 100 次。限额和超时可在 AI 管理中修改，调用记录保存模型、结果和耗时。
演示模式使用固定回复，适合验证词条代理的提案流程。
