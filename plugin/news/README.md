# 活动资讯

安装 `news` 插件后，`新闻` 页面展示已发布的资讯，`特殊:新闻管理` 提供投稿、AI 起草、审核和撤稿。

## 审核与公开版本

投稿需要登录，并具有 `特殊:新闻管理` 的编辑权限。投稿者可以修改自己的草稿。

默认的全稿编辑组为 `管理员|行政员|新闻编辑`，审核组为 `管理员|行政员|新闻审核`。
可以在 `特殊:权限配置` 的“活动资讯”分区修改。用户组须在站点权限管理中创建并分配。

保存稿件后提交审核，审核人员核对来源和正文，再通过“审核通过并发布”公开。
AI 起草走同一流程，生成完成后的状态固定为待审核。

公开内容使用独立快照。编辑已发布新闻时，读者继续看到原公开版本，直到新版本审核通过。
发布时间支持定时发布，首页展示截止和置顶截止会在读取时生效。撤稿立即停止公开。
提交和发布会检查稿件版本，发布时还会检查关联活动的日期、地区、状态是否变化。

正文按文本显示并保留段落。封面使用本站 `/files/` 地址，来源支持 HTTP 或 HTTPS 链接。
消息来源由编辑提交，AI 起草使用粘贴的材料。

新增、修改、提交审核、发布、退回和撤稿写入 `news` 日志，显示在日志页与最近更改中。
未公开或已撤稿新闻的日志仅对有权查看该稿件的人显示；公开日志不包含草稿标题、正文和来源材料。普通查询不记日志。

## AI 起草

在 core 的 `特殊:AI管理` 添加接口，再为“新闻起草”选择站点接口、允许使用的用户组并启用。
默认只有管理员和行政员可以调用。任务队列持久化到数据库，同一账号提交相同材料和来源会返回原任务。
失败后可以重试，中断的任务会在租约到期后恢复。来源材料在成功生成稿件后从任务记录中清除。

## 首页

在 Wiki 源码中写入 `<news-list />` 才会嵌入新闻。首页与其它页面的用法相同，支持多个标签。
插件不会根据“新闻”标题识别模块，不会插入首页模块、移动模块或修改最新页面与活动日历。
列表继承页面字体、颜色和链接样式，适配生产站的 `.mini-block`，不重复生成外层卡片或标题。
在原来的新闻卡片中，用标签替换“占位符”列表即可：

```html
<div class="mini-block">
  <span class="mini-block-title">新闻</span>
  <news-list />
</div>
```

原有英文 News 背景字也可以保留。卡片外框、阴影和首页分栏仍由页面 CSS 决定。
标签默认展示最多六条已审核发布且仍在首页展示期内的新闻，以及全部新闻和投稿入口。
用 `limit` 指定该位置最多展示多少条，例如 `<news-list limit="10" />`。
每个标签独立设置，支持 1–50 条；超过 50 按 50 条，缺省、非正数或无效值按 6 条。
置顶新闻优先，其余按发布时间从新到旧排列；不足指定条数时展示实际可见的新闻。
公开列表接口也支持 `GET /api/news?homepage=true&limit=10`，接口的 `limit` 必须为 1–50。
内容在浏览器中读取公开接口，新闻发布和撤稿随下次载入生效。

列表与草稿接口使用 `Cache-Control: no-store`。草稿、待审核和未来发布的正文不会出现在公开列表和详情接口。
已有缓存的首页也会从接口重新获取公开资讯。

## 数据

插件拥有 `wiki_news`、`wiki_news_revision`、`wiki_news_job` 三张表，由 core 自动建表。
新闻详情通过 `新闻/<ID>` 展示，草稿保存在插件表内。
活动关联通过 common 的 `ActivityDirectory` 获取，安装新版活动插件后可以选择活动和地区。
